# AquaVerse AI — System Audit — 2026-09-10

Branch: `audit/2026-09-10`. Scratch harnesses: `audit_scratch/` (gitignored). No tracked files edited.

**Sandbox constraints (apply to every "BLOCKED" below):** no Docker daemon in this
environment (`docker ps` → cannot connect to the Docker API), so the full stack
(Postgres/TimescaleDB/PostGIS, Redis, MinIO, ARQ worker, MLflow) could not be booted, no
`alembic upgrade head` could be run against a real DB, and every `testcontainers`-based test
(all of `tests/integration/`) could not execute. No GPU, no `unsloth`/CUDA runtime, and no
Flutter SDK were available either. Where the audit brief calls for an executed check I could
not run, this is stated explicitly with what would unblock it (§11). Where I could get a real
answer by reading code, tracing imports, or running an isolated script against installed
`lightgbm`/`pandas`/`numpy`/`pydantic`, I did — those are marked `WIRED` with the command run.

## 1. Verdict

**Readiness tier reached: T1 (component testing), with unusually strong unit-level ML
verification already in place.** The backend boots as a real FastAPI app with substantial
domains genuinely wired to Postgres/SQLAlchemy (this is *not* the all-stub codebase the
repo's own `FIX_PRIORITY.md` describes from 2026-08-17 — most of that list has since been
fixed, per git log `P2.x`/`P3.x` commits). T2 is blocked mainly by: no Docker in this
environment to prove it (not a code defect, an audit-environment limit), and by two P0 code
defects that would fail T2's "no `FORKED` … " and "validator harness passes" gates outright:
**(1)** the number validator's regex only matches ASCII digits, so a hallucinated quantity
spelled as a word or in Tamil numerals passes through completely unchecked (Phase 4 harness,
executed); **(2)** `/v1/reason` — the one endpoint the entire two-layer architecture is
supposed to run through — is still a hardcoded stub, and the one *other* LLM call path that
exists (`POST /v1/advisories/multimodal_reason`) sits outside it entirely and hardcodes
`.to("cuda")` with no fallback. Total: **6 P0, 9 P1, 6 P2** findings below.
**Single biggest blocker:** there is no code-level `sensor_capability` concept anywhere in the
repo (confirmed by an empty grep) — invariant 7 (never assume DO exists) has no enforcement
mechanism to point to at all, and the placeholder M3 feed quantity can reach a farmer with no
gate distinguishing it from a real manufacturer number.
